# 从选中会话向下的惰性发送任务

## 目标

将“一键唤醒”和“跟进已读未回”改为从消息列表中当前选中的会话开始（包含当前会话），向下逐项执行。任务启动后立即处理当前会话，不预先扫描全部列表。每次成功发送后的节流间隔改为 300ms。

## 范围与顺序

- 两个批量功能共用同一套惰性向下遍历机制。
- 启动时必须识别当前选中的会话；无法识别时拒绝启动。
- 当前会话是第一个目标。后续目标按当时列表中的下方顺序取得。
- 不回到列表顶部，不处理起点上方会话，也不执行全量预扫描。
- BOSS 因发信而重排列表时，以发送前已锁定的下一目标为准；不尝试恢复启动瞬间的完整快照顺序。

## 惰性遍历

1. 读取当前选中会话并将其唯一 key 记入已处理集合。
2. 立即对该会话执行现有的切换、就绪、资格与发送流程。
3. 在每次发送前，优先从当前可见列表中锁定它之后的第一个未处理会话。
4. 若没有可见的下一个候选，会小步向下滚动，等待虚拟列表加载后再寻找未处理候选；不会提前滚动或扫描后续全部会话。
5. 每个锁定的目标都以 key 与当时滚动位置保存，激活前仍通过现有的会话匹配校验确认目标正确。
6. 已处理集合防止列表重绘、重复渲染或重排导致重复发送。

## 安全与失败策略

以下现有保护必须保留：排除名单、停止请求、二次会话选择确认、聊天区域和编辑器就绪检查、发送成功确认、已读未回资格判断，以及原有的发送重试。

- 单一会话的定位、切换、聊天加载、资格读取、输入、发送或确认失败：记录失败原因、计入失败数、跳过该会话，并继续后续未处理目标。
- 被排除或不符合已读未回条件的会话：计入跳过数，继续处理。
- 用户请求停止：在当前会话结束后停止，不再选择新会话。
- 无法安全锁定或重新识别下一个目标：结束遍历并上报已完成、跳过、失败和停止状态；绝不退化为处理列表顶部或全量会话。

## 时序

- 保持既有会话切换、聊天加载、编辑器写入、发送确认和失败重试的等待时长。
- 仅将两项批量任务每次成功发送后的间隔统一设为 300ms。

## 界面与测试

- 将两个按钮和运行状态改为“从当前选中会话向下处理”的描述，并展示 0.3 秒发送间隔。
- 为下列纯逻辑添加测试：起点包含当前会话；只选择起点之后的候选；重复项跳过；无后续项结束；单会话错误返回“跳过并继续”；成功间隔为 300ms。
- 现有的安全测试必须持续通过。
